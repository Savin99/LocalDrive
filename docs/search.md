# Чат и поиск по документам: устройство и решения

Спецификация модуля — «Сейф: чат-поиск по документам» от 12.10.2026. Здесь —
что из неё сделано, чем реализация отличается от текста спецификации и какие
факты проверены замером, а не взяты на веру.

## Измерено и прочитано

Окружение замеров: Xcode 27.0 (27A266a), iOS SDK 27.0, macOS 27, симулятор
iPhone 17 Pro на iOS 26.5. Дата — 12.10.2026.

Документация, по которой проверены решения:

- [SQLite FTS5](https://www.sqlite.org/fts5.html): синтаксис запросов (кавычки,
  префикс `"…" *`, фильтр колонок `колонка :`), `bm25()` (меньше — лучше),
  команда `optimize`, опция `secure-delete` (появилась в 3.42.0 и делает
  таблицу нечитаемой для старых версий — поэтому не используется).
- [Стеммер Snowball для русского](https://snowballstem.org/algorithms/russian/stemmer.html)
  и эталонный словарь snowball-data.
- Приказ ФМС России от 30.06.2011 № 279 — правила машиночитаемой записи
  паспорта гражданина РФ: раскладка строк, транслитерация, контрольные цифры.
- ИКАО 9303 — формат TD3 загранпаспорта; образец ERIKSSON ANNA MARIA
  используется в тестах.

## Чем реализация отличается от текста спецификации

- **Облачное распознавание по ключу владельца** — решение от 12.10.2026 после
  сборки 8: локальные модели читали документы плохо. Спецификация запрещала
  сеть, кроме скачивания модели. Теперь фото и сканы из папок, доступных для
  поиска, по желанию владельца уходят в Gemini или OpenAI-совместимый сервис.
  Выключено по умолчанию, суперскрытые и убранные из поиска папки — никогда.
  Текст облака заменяет фрагменты поиска, поля сливаются с правилами. См.
  [cloud-reader.md](cloud-reader.md).
- **Главный экран — чат.** Решение владельца от 12.10.2026: «основная
  страница — чат», библиотека папок — вторая вкладка. В спецификации чат
  открывался из строки поиска на главном экране.
- **Базы с таблицей `Folder` в приложении нет.** Метаданные папок лежат в
  `Vault/vault.json`, файлы читаются прямо с диска. Флаг `searchable` добавлен
  в `VaultFolder`, а индекс — новая SQLite-база
  `Application Support/SearchIndex/index.sqlite`.
- **Индекс лежит вне `Vault/`.** Резервная копия шифрует всё содержимое
  `Vault/` и при восстановлении подменяет каталог целиком. Живая база внутри
  него попала бы в копию в несогласованном виде и была бы затёрта при
  восстановлении. Индекс производный: после восстановления он строится заново.
  Защита та же, что у файлов: `FileProtectionType.complete` на каталоге и
  `SQLITE_OPEN_FILEPROTECTION_COMPLETE` при открытии, плюс исключение из
  резервных копий iOS. Следствие: ручные правки полей живут только в индексе и
  после восстановления на новом iPhone не переносятся.
- **`fileId` — это пара «папка + имя файла».** Своих идентификаторов у файлов
  нет, файл однозначно задаётся этой парой.
- **Морфология — стеммер Snowball, а не лемматизатор.** Леммы `NLTagger` на
  iOS зависят от языковых ассетов, которых может не быть на устройстве;
  индекс и запрос должны разбираться одинаково всегда.
- **Встроенная модель Apple не подходит и в поколении 27** — русского нет
  (замер выше). Свободные вопросы в чате — только своя модель (этап 5), см.
  [llm-ondevice.md](llm-ondevice.md).
- **«Паспорт» без уточнения — паспорт РФ.** В таблице сценариев на «мой
  паспорт» при двух паспортах шли только чипы. Владелец попросил, чтобы
  «паспорт савина илья» сразу давал данные и файл. Теперь ответ — данные
  паспорта РФ, а загранпаспорт остаётся чипом «Ещё есть» под ответом.
- **Развороты паспорта — один документ.** Паспорт РФ обычно снимают двумя
  фото: на одном ФИО и MRZ, на другом «кем выдан» без имени. Если в одной папке
  один разворот с именем и остальные без него, чат отвечает одной группой
  карточек. Каждая карточка ведёт к своему файлу. Если в папке паспорта
  нескольких людей, разворот без имени не прикладывается ни к одному: чей он,
  по тексту не понять, а чужое «кем выдан» хуже пустого.
- **Паспорта других стран** — тот же тип, что загранпаспорт (паспорт по ИКАО),
  с полем «страна». В чате это «Паспорт Таджикистана», а не «загранпаспорт».
  Отдельный тип потребовал бы менять промпт и грамматику модели без нового
  прогона стенда. Имя ищется во всех паспортах сразу: «паспорт Рахимова» без
  слова «иностранный» находит паспорт Таджикистана. В «Какой нужен?»
  попадают все паспорта, а не только паспорта РФ.
- **Чип уточнения указывает документ напрямую** (`documentId` в варианте).
  Два паспорта РФ одного человека из разных папок повторным текстом не
  различить; подписи таких чипов дополняются названием папки.
- **Оформление — в духе ChatGPT** (белый, почти чёрный, серые поверхности и
  рамки, зелёный акцент). Нижние вкладки «Чат» и «Файлы» владелец оставил.

## Как устроено

```
импорт файла ─► VaultStore ─► SearchIndexer (actor) ─► DocumentTextExtractor ─► Vision OCR
                    │               │  сверка с диском, очередь, по одному файлу
                    │ события       ▼                    DocumentAnalyzer: тип и поля (MRZ, подписи)
                    └──────────► SearchIndexStore (SQLite: document, chunk, chunk_fts, field)
                                    ▲
вопрос в чате ─► ChatRouter ────────┤  тип документа, поля, имя владельца, срок
               └► SearchService ────┘  FTS5 (слова + основы) и совпадение с папками → RRF
ответ: текст + карточки (только documentId и ключи полей) ─► ChatCardResolver ─► значения из базы
```

- **Что индексируется.** Только папки, у которых `searchable` включён и
  которые не суперскрытые. Суперскрытая папка не попадает в индекс вообще; её
  данные удаляются из базы в момент скрытия, а каждый запрос дополнительно
  ограничивается списком разрешённых папок на случай гонки. Команды в индекс
  идут строго по очереди: сверка, снятая до скрытия папки, не может выполниться
  после него.
- **Извлечение текста.** PDF — текстовый слой PDFKit, страницы без текста
  рендерятся и распознаются. Фото — Vision `.accurate`, языки `ru-RU` и
  `en-US`, порог высоты текста 0. Текстовые файлы читаются как UTF-8, UTF-16
  или Windows-1251. Офисные документы — OCR первой страницы из превью
  QuickLook. Видео и аудио ищутся только по имени.
- **Морфология.** Для каждого фрагмента хранятся две колонки FTS5: слова
  (нижний регистр, «ё» → «е») и основы Snowball. Слово запроса подходит, если с
  него начинается слово текста или совпадает основа. Если ни один документ не
  содержит всех слов, поиск повторяется с «или».
- **Поля.** Сначала MRZ с проверкой контрольных цифр (паспорт РФ по приказу
  № 279, паспорта по ИКАО 9303), затем подписи на странице («Паспорт
  выдан», «Код подразделения»). Уверенность: своя контрольная цифра поля
  сошлась — 0,99; не сошлась, но совпала с подписью — 0,9; не сошлась — 0,4;
  только подпись — 0,6. Ниже 0,9 поле помечается в карточке для сверки с фото,
  пока человек его не подтвердит. Цифра проверяется у каждого поля своя:
  ошибка в дате рождения не роняет доверие к номеру.
- **ФИО из MRZ.** Контрольной цифры у имени нет, а Vision читает «<» как
  «K». Поэтому каждая «K» на стыке слов — либо буква, либо заполнитель
  (`MRZNames.swift`). Из вариантов выбирается тот, чьи слова напечатаны на
  странице. Без них выбор идёт по строению: фамилия, имя, отчество; без слов
  из одних «К» и без «КК»; с наименьшим числом замен. Подтверждённое страницей
  имя — 0,99, совпавшее с подписью «Фамилия … Имя …» — 0,9, остальное — 0,6,
  то есть на сверку.
- **Паспорт по ИКАО.** Код страны берётся из первой строки и сверяется с
  гражданством во второй. У паспортов стран СНГ ФИО кириллицей напечатано
  рядом с латиницей. Оно берётся со страницы, если каждое слово MRZ находит
  пару по таблицам транслитерации (`ForeignPassport.swift`): у стран они
  разные, «Ёдгор» в Таджикистане — YODGOR, а по ИКАО было бы EDGOR. Отчество — из
  той же строки. Даты выдачи в MRZ нет: она ищется по сроку действия, ведь
  паспорт выдают на 10 или 5 лет, и срок кончается в тот же день или накануне.
  Подпись над значением часто стоит в другой колонке. Найденная так дата —
  0,9, только по подписи — 0,6. Орган — после подписи «Authority» или «Кем
  выдан», 0,6.
- **Удаление.** `PRAGMA secure_delete`, после очистки папки — `optimize`
  индекса FTS5: старые сегменты индекса сливаются, освобождённые страницы
  затираются. Журнал отката вместо WAL: после коммита он удаляется вместе со
  своим ключом шифрования.
- **Переиндексация.** У каждого документа есть `index_version`. Когда версия в
  коде растёт, документы перечитываются в фоне; ручные правки полей
  сохраняются.
- **Чат.** Роутер на правилах понимает тип документа, нужные поля, вопрос о
  сроке и имя владельца («паспорт савина илья»: основы «савин», «ил»; для
  загранпаспорта — латиница по ИКАО). Ответ — короткий текст и карточки из
  каталога: `fields`, `document`, `fileList`, `snippet`, `clarify`, `expiry`.
  В карточке только `documentId` и ключи, значения подставляет рендерер из
  базы. Номер документа замаскирован, открывается после Face ID. Копирование —
  в буфер только этого iPhone на 2 минуты. Переписка живёт в памяти, пока
  работает приложение. Блокировка при уходе в фон убирает экран, но не стирает
  её, а номера снова закрывает маской. На диск история не пишется.
- **Уточнения.** Вопрос без типа и имени («а дата выдачи?», «код
  подразделения?») относится к документу из прошлого ответа. Если в вопросе
  есть ещё слово («номер договора»), это поиск по тексту.
- **Адрес** полем не распознаётся: штампы регистрации слишком разные. На
  «адрес какой», «где прописан» чат показывает страницу «Место жительства»
  из папки паспорта: из прошлого ответа или по имени в вопросе. Если в папке
  паспорта нескольких людей, он говорит, что чья страница — видно на фото.
  Если страницы нет, просит её добавить.

## Этапы

| Этап | Статус |
| --- | --- |
| 1. Индекс и поиск по тексту | сделан, проверен тестами и в симуляторе |
| 2. Поля паспорта | сделан для паспорта РФ и загранпаспорта; проверка на своих сканах — за владельцем |
| 3. Смысловой поиск | не начат: нужна модель эмбеддингов в Core ML |
| 4. Чат и карточки | сделан: роутер на правилах, шесть карточек, проверено тестами и в симуляторе |
| 5. Локальная LLM | встроена: Qwen3-4B через MLX, план по грамматике без цифр, откат на правила; на стенде 91% планов точно, 100% валидный JSON; на iPhone не проверена |
| 5б. Модель для документов | встроена (сборка 7): Qwen3.5-4B вторым чтением удостоверений, необязательная загрузка 3,06 ГБ; на 34 синтетических кадрах ФИО 25 → 29, даты 27 → 33, ложные значения все с пометкой «проверьте» ([doc-reader.md](doc-reader.md)); память и скорость на iPhone не проверены |

Решения по открытым вопросам спецификации, принятые по умолчанию до ответа
владельца:

- Минимальная версия iOS — 26.0 (решение владельца от 12.10.2026, сборка 4):
  при цели 18.0 в приложение попадала библиотека совместимости
  `libswiftCompatibilitySpan.dylib`, и подпись в IPA Shelf её отклоняла.
- Папки-ленты: индексируются их вложения, текстовые блоки ленты — нет
  («ищем только по файлам»).
- История чата на диск не пишется. Сначала она пропадала и при каждой
  блокировке. Владелец 12.10.2026: «из приложения выхожу — всё пропадает, чат
  с нуля». Теперь переписка живёт до перезапуска приложения.
- Типы документов после паспортов: СНИЛС, ИНН, права, диплом и справка
  распознаются по ключевым словам, но полей пока не получают.
