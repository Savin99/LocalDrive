# Локальная модель для чата: что выяснено

Этап 5 спецификации: свободные вопросы в чате без облака. Здесь — проверенное
по исходникам и документации на 12.10.2026. Что не проверено — так и помечено.

## Почему не модель Apple

`SystemLanguageModel.default` (Foundation Models) на macOS 27 поддерживает 24
локали, русского среди них нет: `supportsLocale(ru_RU) == false`. Замер на этом
Mac, см. [search.md](search.md).

## Пакеты

- **mlx-swift-lm 3.32.3** (2026-09-30) — библиотеки MLXLLM, MLXLMCommon и
  MLXGuidedGeneration переехали сюда из mlx-swift-examples. Нужны
  swift-tools 6.2 и iOS 17.
- **mlx-swift 0.32.3**, продукт MLX: `Memory.*` наружу не реэкспортируется.
  Версии 0.31.5–0.31.6 ломали неинтерактивный `xcodebuild` из-за плагина
  `CudaBuild` (mlx-swift-lm PR #404) — брать 0.32.x и новее.
- В 3.x своего загрузчика и токенизатора нет:
  - **swift-transformers 1.3.5**, продукт Tokenizers;
  - **swift-huggingface 0.13.0**, продукт HuggingFace.
- Макро-продукт `MLXHuggingFace` не подключаем: Xcode требует подтвердить
  доверие макросу. Его код — около 40 строк, пишется руками.
- Работает ли сборка `MLXCXGrammar` с `.unsafeFlags(["-w"])` в Xcode 27 —
  **не проверено**.

## Загрузка и хранение

- Скачивание один раз, с отдельного экрана настроек. Это единственный выход в
  сеть: `HubClient.downloadSnapshot`.
- Ревизия закрепляется хэшем коммита. Только тогда клиент берёт модель из кэша
  без сети; с `main` он каждый раз ходит в сеть за списком файлов.
- Каталог — `Application Support/LLM`, исключён из резервных копий. Кэш по
  умолчанию — `Library/Caches`, а его система периодически чистит.
- Прерванное скачивание продолжается с места обрыва (HTTP Range).
- Веса публичные, класса защиты по умолчанию для них достаточно.

## Как модель отвечает

Модель — планировщик, а не автор карточек. Она получает вопрос, короткую
опись документов без значений и последние реплики, а возвращает `ChatPlan`
(`Sources/Chat/ChatPlan.swift`). План исполняет тот же код, что и роутер на
правилах, а карточки заполняются из базы.

- Вывод ограничивается JSON-схемой через MLXGuidedGeneration (XGrammar
  v0.1.30). Тип документа, ключи полей и действие — перечисления из каталога.
- Поле `text` получает шаблон без цифр. Тогда напечатать номер документа модель
  не может технически, а не только по инструкции. Диалект регулярных выражений
  в XGrammar — **проверяется на стенде**.
- Декодирование при грамматике жадное. Первая компиляция грамматики занимает
  сотни миллисекунд — не на главном потоке, с прогревом.

## Замер на стенде (12.10.2026)

Apple M4, 16 ГБ, macOS 27, Xcode 27; mlx-swift-lm 3.32.3, mlx-swift 0.32.3,
swift-transformers 1.3.5, swift-huggingface 0.13.0. 34 русских вопроса:
сценарии спецификации, разговорные варианты и опечатки, уточнения с историей,
болтовня, попытка заставить напечатать номер. Генерация жадная, `maxTokens` 220,
грамматика EBNF.

| | Qwen3-4B-Instruct-2507-4bit | Qwen3.5-2B-4bit |
| --- | --- | --- |
| Ревизия | `50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b` | `674aaa7240b91e8012fcad5d791b7dfe5ba90207` |
| Скачивание | 2173 МБ | 1668 МБ |
| Загрузка | 1,1–1,5 с | 0,9–1,3 с |
| Память MLX: активная / пик | 2160 / ≈2830 МБ | 1011 / 1642 МБ |
| До первого токена, медиана | 3,02 с | 0,99 с |
| Весь ответ: медиана / максимум | 3,79 / 4,20 с | 1,55 / 3,74 с |
| JSON валиден / план точно / действие верно | 100% / 91% / 100% | 94% / 59% / 91% |

Выводы:

- **Модель одна — Qwen3-4B.** Qwen3.5-2B как планировщик не годится: петли
  («ы ы ы»), пустые типы, болтовня в `query`. На iPhone, где памяти на 4B не
  хватает, чат остаётся на правилах.
- **Три промаха 4B — в поиске:** пустой `query` или имя соседнего ключа. Их
  закрывает правило `ChatRouter.searchQuery`: запрос модели берётся, только если
  у него есть общая основа с сообщением.
- **Ни одной цифры в ответах**, включая попытку инъекции. Чёрный список
  `[^0-9]` модель обходит иероглифами («五年»), поэтому в грамматике белый список
  символов. Без грамматики обе модели пишут «в 45 лет».
- **Ключ ответа — `reply`, а не `text`:** с `text` модель вписывала само слово
  в соседнее поле.
- Почти всё время уходит на разбор системного промпта (≈1200 токенов). Кэш
  префикса есть только внутри `ChatSession`, а цикл генерации с грамматикой
  каждый раз начинает с пустого. Свой цикл с переиспользованием кэша — главный
  резерв скорости.
- `GrammarConstraint.clone()` не работает (`forkFailed` в xgrammar 0.1.30):
  грамматика собирается на каждый запрос, это 20–36 мс. Ограниченные повторы
  `{0,240}` в шаблонах поднимали время до 2,3–3,6 с — их нет.
- Смещения закрытия и пробелов из `MLXFoundationModels` портят строки — не
  используются.
- Задержка на iPhone **не измерена**: проверка на устройстве — за владельцем.

Итоговые промпт и грамматика — `Sources/Chat/LLM/ChatModelPrompt.swift`.

## Qwen3.5 4B вместо Qwen3 4B? Замер 12.10.2026, вечер

Вопрос: может ли одна модель «текст + картинка» и разбирать вопросы чата, и
читать документы (docs/doc-reader.md)? Тогда хватило бы одной загрузки.

Те же 34 вопроса, промпт и EBNF дословно из `ChatModelPrompt.swift`, генерация
как в приложении: грамматика на каждый запрос, без смещений. Qwen3.5 4B
загружена контейнером MLXVLM, как в приложении для документов (цель `PlanVLM`
стенда). Qwen3 4B — прежний стенд, прогон в тот же час на той же машине.

| | Qwen3.5-4B-4bit `0e7ffd5c…` | Qwen3-4B-Instruct-2507-4bit |
| --- | --- | --- |
| Валидный JSON | 97 % (1 из 34 не уложился в 220 токенов) | 100 % |
| План точно | 88 % | 91 % |
| Действие верно | 97 % | 100 % |
| Цифры в ответе | 1 (`query` из нулей в недописанном JSON) | 0 |
| Весь ответ, медиана / максимум | 3,73 / 8,59 с | 3,80 / 4,16 с |
| Пик памяти MLX | 3,62 ГБ | 2,83 ГБ |

Промахи Qwen3.5 4B: пустые `types` у «паспорт савина илья», «паспорт жены»,
«когда заканчивается загранпаспорт мамы» и бесконечная `query` у «номер
загранника». Порог был: JSON и действие — 100 %, план — не хуже 91 %, ни одной
цифры. **Не прошла: чат остаётся на Qwen3 4B**, Qwen3.5 4B — отдельная
необязательная модель для документов.

## iPhone

- **iPhone 16 Pro Max владельца без entitlement: «Доступно приложению: 3,24
  ГБ»** (экран настроек, сборка 7, 12.10.2026). Модели чата (нужно 3 ГБ)
  хватает, Qwen3.5 4B для документов (4 ГБ) — нет. Для таких iPhone есть
  облегчённая Qwen3.5 2B, см. docs/doc-reader.md.
- Entitlement `com.apple.developer.kernel.increased-memory-limit` все примеры
  MLX добавляют, а LocalDrive — нет. Владелец переподписывает IPA присланными
  профилями (`IPA_RELEASE.md`), и ограниченный entitlement может сорвать
  подпись. Вместо этого перед загрузкой проверяется
  `os_proc_available_memory()`. Пик 4B на Mac — ≈2,83 ГБ; если доступно меньше,
  модель не загружается, и чат отвечает на правилах.
- В симуляторе MLX не работает: нужен современный `MTLGPUFamily`. Модель
  прячется за `#if targetEnvironment(simulator)`, и чат там отвечает на правилах.
- В фоне iOS отклоняет команды GPU. Когда приложение уходит с экрана,
  генерация отменяется, и дожидаемся `synchronize()`.
- Первый вызов скомпилированных функций MLX медленный — после загрузки нужен
  короткий прогрев.

## Модель чата не вытесняется и не ждёт впустую — 24.10.2026

Жалоба владельца: «дата рождения Ольги» — больше 30 с «думал», хотя паспорт
загружен; потом «фигню какую-то преподносит». Разбор по коду:

1. После смены модели документов (см. cloud-reader.md, «Смена модели»)
   фоновое чтение перечитывало все удостоверения.
2. В памяти iPhone одна модель (`ModelResidency`). Каждый вопрос выгружал
   модель документов и грузил модель чата, а фоновое чтение сразу после
   ответа делало наоборот — следующий вопрос снова ждал загрузки.
3. Планировщик ждал до 20 с, и только потом отвечали правила.
4. «Дата рождения Ольги» без слова «паспорт» правила не понимали как вопрос о
   человеке — ответом был поиск по тексту.

Что сделано:

- **Правила — первыми, при любом чате** (`ChatSession.send`). Точный ответ из
  базы (`ChatReply.isConfident` или прежний `isConfidentLookup`) показывается
  сразу; модель и облако получают только то, что правила не поняли.
- **Человек без вида документа** (`ChatRouter.person`): «дата рождения Ольги»,
  «сколько лет Илье», «что есть на Ольгу», «Ольга». Люди — по ФИО из полей
  всех документов; двое с одним именем — вопрос «о ком?» чипами; опечатка в
  имени — «Похоже, вы про …»; слово сверх имени («договор Ольги») — поиск по
  тексту.
- **Уточнения с «а»** (`ChatIntent.continuing`): «а загран?» после «номер
  паспорта» — номер загранпаспорта; «а у Ольги?» после «дата рождения Ильи» —
  её дата. Раньше это понимала только модель.
- **Чат важнее фонового чтения**: вопрос к модели отмечает
  `ModelResidency.noteChatActivity()`, и модель документов минуту не
  грузится (`waitForChatPause`), не вытесняя модель чата.
- **Срок планировщика — 10 с вместо 20.** Не успела — правила, а шаг ленты
  так и говорит: «Модель не успела — отвечаю по базе».

Проверено: `ChatPersonTests` (12 сценариев), `ChatModelTests`
(`testEllipticFollowUpIsAnsweredByRules` и обновлённые тесты планировщика: в
модель уходят только вопросы, которые правила не поняли). На iPhone время не
мерено — проверка за владельцем.

## «Какой день рождения у этого человека?» — сборка 16, 24.10.2026

Владелец на iPhone: загрузил паспорт, спросил — ответа нет. Три причины:

1. **«День рождения».** Правила знали «дата рождения» и «родился», а слово
   «день» оставалось словом имени: «какой день рождения у Ольги» искал
   человека «День Ольга» и уходил в поиск по тексту. Теперь «день», «дня»,
   «днюха», «др» рядом с «рождения» — часть вопроса.
2. **«Этого человека», «у него», «её»** тоже считались именем. Теперь это
   ссылка назад (`ChatIntent.refersBack`): на документ прошлого ответа, а
   если его нет — на удостоверение, добавленное за последние полчаса. Без
   ссылки и без имени вопрос о поле — как «паспорт» без имени: один человек —
   ответ, несколько — «чей?» чипами.
3. **Паспорт, брошенный в чат через «+»,** в базу не попадает, пока его не
   разложат «Выполнить». Теперь чат читает вложение сразу (тот же разбор, что
   у индекса: Vision, MRZ, подписи), запоминает прочитанное на время
   переписки и отвечает по нему: «По вложению «скан.jpg» (Паспорт РФ —
   Иванова А. С.): Дата рождения: 12.05.1985». В ответе на само вложение
   сказано, что это и чьё. Вопрос вместе с файлом — ответ и предложение папки.

Если поле ещё распознаётся (очередь Vision, облака или модели не пуста), чат
так и говорит — «появится через минуту», а не «не распознано».

Проверено: `ChatPersonTests` (5 новых сценариев) и живая проверка — шаги C7
«какой день рождения у этого человека?» и C8 «какой день рождения у Ильи»,
3/3, меньше 0,05 с.
